2. AUTHENTICATION & BOOT ARCHITECTURE
-------------------------------------------------------------------------------
- startup.lua validates credentials before executing the core desktop environment[cite: 3].
- Password Hashing Algorithm:
  Passwords are processed using a DJB2 bitwise hash function[cite: 3]:

  hash = 5381
  for each byte in password:
    hash = bit32.band(bit32.lshift(hash, 5) + hash + byte, 0xFFFFFFFF)
  return string.format("%08x", hash)

- User Credentials Format (`user_files/account.txt`)[cite: 3]:
  Line 1: <username>[cite: 3]
  Line 2: <hex_hashed_password>[cite: 3]

3. HOMESETINGS CONFIGURATION FORMAT
-------------------------------------------------------------------------------
File location: `/user_files/homesetings.text`[cite: 4]
Parameters are stored as space-delimited string key-value pairs with trailing "d" markers[cite: 4]:

Key Examples:
- `loadingScreen=gray def`[cite: 4]
- `homeColor=magenta de`[cite: 4]
- `taskbarColor=gray d`[cite: 4]
- `pointerColor=yellow de`[cite: 4]
- `comModem=1 d`[cite: 4]
- `super_x=2 d` / `super_y=2 d` (Saved app positioning)[cite: 4]

Custom Button Entries:
Format: `btn_<id>={label="<label>",bg=<color_enum>,path="<path>",x=<x>,y=<y>} d`[cite: 4]

-------------------------------------------------------------------------------
4. WEB OS FRAMEWORK DEVELOPMENT (`net/`)
-------------------------------------------------------------------------------
The HomeOS mesh web infrastructure separates frontend display logic from backend
server routing.

A. Frontend Site Scripts (`net/share/<appname>.lua`)
   - Served by `ServerHost.lua` over Rednet (protocol "homeos_mesh").
   - Downloaded and executed locally by `WebViewer.lua`.
   - Accesses screen dimensions via local window canvas limits.
   - Has access to the injected global `net` table for browser navigation.

B. Backend Server Modules (`net/modules/<appname>_module.lua`)
   - Loaded into memory by `ServerHost.lua` when the corresponding site in
     `net/share/` is marked active.
   - Modules receive the `serverAPI` object as varargs (`...`).
   - Registration functions available in modules:
     1) `api.registerPacketHandler(packetType, function(senderID, packet))`
        Processes incoming Rednet packets over protocol "homeos_mesh".
     2) `api.registerCommand(cmdName, desc, usage, function(args))`
        Exposes backend CLI management commands directly into the ServerHost
        terminal interface.

C. Persistent Database Storage (`net/site_data/<appname>/`)
   - Backend modules must read/write persistent application state inside
     `net/site_data/` to ensure isolated storage.
